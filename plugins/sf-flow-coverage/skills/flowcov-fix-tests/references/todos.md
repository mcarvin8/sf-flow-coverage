# TODOs in generated Flow tests

What each kind of TODO means, and what to do about it. The `kind` comes from `sf flowcov scaffold --json`. TODOs without a kind are listed after the table.

| Kind                                                                                              | What it means                                                                                          | What to do                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entry criteria`, `entry criteria formula`, `entry criteria formula term`, `entry criteria logic` | The test couldn't set field values that meet part of the Flow's start conditions.                      | Read the Flow's `<start>` filters and `filterFormula`, and set field values on the test record that meet them. Use the field's type from the object's metadata or `sf sobject describe`.                                                                                                                                         |
| `decision`                                                                                        | A decision the test couldn't steer.                                                                    | Usually leave it. Steer it only to cover a branch the user asked for.                                                                                                                                                                                                                                                            |
| `validation rule`                                                                                 | An active validation rule would block the save, and the test couldn't avoid it.                        | Read the rule's formula. Run `sf data query --use-tooling-api -q "SELECT Metadata FROM ValidationRule WHERE ValidationName = '<Name>'" -o <org> --json`, or find it under `objects/<Object>/validationRules` in the project. Set field values that keep it from firing, such as a status it exempts or a parent record it needs. |
| `lookup filter`                                                                                   | A required lookup filter rejects the parent record the test inserts.                                   | Read the filter on the lookup field, under `objects/<Object>/fields/<Field>.field-meta.xml` in the project or with a Metadata API retrieve. Give the parent record the values the filter needs.                                                                                                                                  |
| `email recipient`                                                                                 | A Send Email action or email alert sends to a field the test couldn't fill.                            | Set an address such as `flowtest@example.com` on the field, or on the record it points to.                                                                                                                                                                                                                                       |
| `record type`                                                                                     | The record type the test needs isn't available to the running user, or doesn't allow a picklist value. | **Org change:** the record type has to be assigned to the test user's profile or a permission set. Report it.                                                                                                                                                                                                                    |

TODOs without a kind:

- **"the Flow uses fields the user who generated this test can't see"** (header): the test user may lack field-level security on those fields. If the test fails with "fields being inaccessible", it's an **org change**: a permission set granting access. Report it.
- **"this Flow submits ... for approval"** or **"... submits a ... for approval when it's created and again when it's updated"** (header): the save can fail with `ALREADY_IN_PROCESS`.
  - Check the other automation's entry criteria. If the test can leave them unmet without changing what it tests, do that.
  - Otherwise report it: whether a record should be submitted is the org's business rule.
- **"set a X Id" / "set Field__c: ..."** on a field value: a lookup the test couldn't fill.
  - Insert a parent record with its required fields, and use its Id.
  - When the TODO says the lookups form a cycle, the data model needs an existing record or an optional lookup. Report it.
- **"fill input.X__r.Field__c: the Flow reads it"**: give the input record's lookup a parent record that has a value in that field.
- **"insert a X record for Element to delete"**: insert a record that matches the Delete Records element's filters before `Test.startTest()`.
- **"the Id of a X record" / "the Id of the record X.Y points to"**: insert a record of that object and pass its Id as the input.
- **"query and assert the fields this Flow sets"** and **"assert what this Flow does"**: replace with real assertions based on the Flow's elements (Step 3 of the skill).
- **"this Flow runs for X records on a schedule; $Record is not set when started from Apex"**: a test can't set `$Record` for a schedule-triggered Flow. Report that the logic needs to move to an autolaunched subflow that takes the record as an input. Don't rewrite the Flow.
