# Test failures and what to do

Look up the error from `sf apex run test`. **Test** means fix the test's data. **Org** means report it: the org needs a change, and the test shouldn't work around it.

| Error contains                                                                             | Fix in        | What to do                                                                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------ | ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FIELD_CUSTOM_VALIDATION_EXCEPTION`                                                        | Test          | Find the rule by its message, read its formula, and set values that keep it from firing (see `validation rule` in [todos.md](todos.md)).                                                                                                       |
| `FIELD_FILTER_VALIDATION_EXCEPTION`                                                        | Test          | A lookup filter rejects the parent: give the parent the values the filter needs.                                                                                                                                                               |
| `REQUIRED_FIELD_MISSING`                                                                   | Test          | Set the named fields.                                                                                                                                                                                                                          |
| `INVALID_OR_NULL_FOR_RESTRICTED_PICKLIST`                                                  | Test or Org   | Check the field's values for the record's record type, and whether it depends on another picklist. If so, set the controlling field to a value the dependency allows. If no record type the user can use allows the value, it's an org change. |
| `INVALID_CROSS_REFERENCE_KEY` ... `Record Type ID: this ID value isn't valid for the user` | Org           | The test user can't use that record type. It needs to be assigned to their profile or a permission set.                                                                                                                                        |
| `Operation failed due to fields being inaccessible`                                        | Org           | Automation running as the test user touches fields they can't access. The fix is a permission set that grants them. Name the fields from the class header TODO.                                                                                |
| `ALREADY_IN_PROCESS`                                                                       | Org (usually) | The record is already in an approval process. See the approval TODO in [todos.md](todos.md).                                                                                                                                                   |
| `0 recipients` / `EMAIL_NOT_PROCESSED_DUE_TO_PRIOR_ERROR`                                  | Test          | Give the record the email address the Send Email action or alert sends to. For an alert, read its recipients (`WorkflowAlert` metadata) to find the field.                                                                                     |
| `No records in Salesforce match your delete criteria`                                      | Test          | Insert a record matching the Delete Records filters before the Flow runs. For a filter on `CreatedDate`, insert the record and then call `Test.setCreatedDate(record.Id, ...)`.                                                                |
| `hasn't been set or assigned`                                                              | Test          | The Flow reads a field the input record doesn't hold. Query that field (and any relationship path) after inserting the record, and give its lookups parent records.                                                                            |
| `the ID value in the variable must be populated`                                           | Test          | The Flow updates or deletes a record variable without an Id. Find where the variable gets its value, usually an input Id or a Get Records, and give the test a real record for it.                                                             |
| `Invalid id` / `invalid ID field`                                                          | Test          | Text was passed where a record Id belongs. Insert a record and pass its Id.                                                                                                                                                                    |
| `Apex CPU time limit exceeded`                                                             | Test          | Usually a loop that never ends for the placeholder inputs, such as splitting text on a delimiter it doesn't contain. Read the Flow's loop and give the inputs values that let it finish.                                                       |
| `Missing required input parameter: SObjectRowId`                                           | Org           | A schedule-triggered Flow's email alert needs `$Record`, which a test can't set. Report that the logic needs to move to an autolaunched subflow.                                                                                               |
| `MIXED_DML_OPERATION`                                                                      | Test          | Insert setup records (users, groups, roles) inside `System.runAs(new User(Id = UserInfo.getUserId())) { ... }`.                                                                                                                                |
| `Assertion Failed`                                                                         | Test          | Re-check the expected value against the Flow's elements for the data the test sets. Fix the assertion only if the Flow really does something else, and say so in the report.                                                                   |
| `UNABLE_TO_LOCK_ROW`, `Too many SOQL queries`, other limits from other automation          | Org (report)  | Other automation on the object runs in the same transaction. Report it rather than reshaping the test around it.                                                                                                                               |
